# Voice model audit — 13 November 2026

The extension's **voice active** switch previously meant only that hover handling was enabled. The audio request still depended on a separate neural service that was offline, so the page stayed silent. The UI now reports synthesis failure. The Railway API can use OpenRouter speech for Hausa and Fulfulde when `ENABLE_OPENROUTER_SPEECH=true`; the OpenRouter key remains server side. Both languages returned non-silent PCM in live requests, then the API wraps it as WAV. This proves transport and audible output, not accent or linguistic correctness.

The Meta and CLEAR Global checkpoints are not deployed on Railway. Their licenses prohibit commercial use without separate permission. The community Ewondo checkpoint has no stated license. A production voice release also needs a native-speaker listening evaluation for the exact variety, a documented corpus, and latency/cost measurement. A non-silent waveform alone is insufficient.

The current Android and extension pilots support **text translation** for five configured targets. Speech is available through the hosted API only for Hausa and Fulfulde after a user configures a scoped API key. The Android browser uses long press; the desktop extension uses hover or click. Ewondo, Kanuri, and Cameroon Pidgin remain silent rather than substituting an unrelated voice.
