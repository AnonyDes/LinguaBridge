# Voice model audit — 13 November 2026

The extension's **voice active** switch previously meant only that hover handling was enabled. The audio request still depended on a separate neural service that was offline, so the page stayed silent. The UI now reports synthesis failure. The Railway API uses OpenRouter speech for Hausa and Fulfulde when `ENABLE_OPENROUTER_SPEECH=true`. When `ENABLE_EXPERIMENTAL_SPEECH=true`, it also attempts Ewondo, Central Kanuri target text, and Cameroon Pidgin target text. The OpenRouter key remains server side. All five requests returned non-silent PCM in live probes, then the API wraps it as WAV. This proves transport and waveform generation, not accent, intelligibility, or linguistic correctness.

The Meta and CLEAR Global checkpoints are not deployed on Railway. Their licenses prohibit commercial use without separate permission. The community Ewondo checkpoint has no stated license. A production voice release also needs a native-speaker listening evaluation for the exact variety, a documented corpus, and latency/cost measurement. A non-silent waveform alone is insufficient.

All five local listening samples are in `models/voice-audit/` (ignored by Git). Short copies are published in `apps/web/public/voice-samples/` and identified by their actual checkpoint and language variety at `/voices`. They are fixed recordings for listening, not arbitrary text synthesis or evidence of linguistic accuracy. The four Meta recordings carry their CC BY NC 4.0 source attribution; the Ewondo community checkpoint has no stated license.

The current Android and extension pilots support **text translation** for five configured targets. Hosted speech requires a scoped API key. Hausa and Fulfulde use documented TTS language support; Ewondo, Kanuri, and Cameroon Pidgin use explicitly experimental TTS whose language quality is unknown. The Android browser uses long press; the desktop extension uses hover or click. A successful audio response only confirms that sound can be played.
